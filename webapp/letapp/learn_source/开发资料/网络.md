## 第 0 章 认识计算机网络：它到底是什么

### 0.1 先讲一个真实场景

你每天打开微信、刷抖音、用淘宝、看网页——这些背后全是**计算机网络**在干活。
如果有一天全世界断网，你立刻会感觉到：微信发不出去、外卖点不了、视频刷不出来。可见网络已经和水电一样重要。

那到底什么是"计算机网络"？别急，先看下面这个 3 秒钟就能懂的生活类比。

### 0.2 生活类比：电脑是一座座"小房间"

想象每一台电脑都是一间**独立的房间**：

- 房间里堆着你的**资料**（照片、文档、软件）。
- 每间房都有自己的**门牌号**（对应后面要讲的 IP 地址）。
- 你想把资料给隔壁房间的人，最笨的办法是：**把 U 盘插过去拷贝**，还得人亲自跑过去。
- 如果全世界房间之间都修好**路、装了信使**，那你坐在房间里就能把资料一秒送到千里之外——这就是网络。

所以一句话定义：

> **计算机网络 = 把两台或多台独立的计算机设备用通信线路连接起来，让它们之间能够交换信息、共享资源的一整套系统。**

### 0.3 网络解决的三个痛点（没有它会怎样）

| 痛点 | 没有网络时（多痛苦） | 有网络后（多方便） |
|------|-------------------|------------------|
| **传信息慢** | 靠 U 盘、光盘人肉拷贝，快则几小时慢则几天 | 文件秒传，跨越大洋只需几秒 |
| **资源共享难** | 每台电脑都得自己装软件、存数据，重复劳动 | 服务器存一份，成千上万人共享 |
| **距离受限** | 只能近距离交流 | 全世界实时互联互通 |

> **核心结论（先记住）**：网络存在的意义就是**传递信息 + 共享资源**，让远隔千里的人和机器能"像面对面一样"协作。

### 0.4 网络里的三个角色

任何一次网络交流，几乎都离不开这三种角色：

| 角色 | 通俗解释 | 真实例子 | 类比 |
|------|---------|---------|------|
| **客户端 Client** | 主动"提要求"的一方，等结果的人 | 你的浏览器、微信 App、抖音 App | 去餐厅点餐的**顾客** |
| **服务器 Server** | 一直"等请求、满足请求"的一方 | 淘宝后台、游戏服务器、视频网站服务器 | 餐厅的**厨房/厨师** |
| **网络设备** | 帮忙"传信"的中间人 | 路由器、交换机、光猫、基站 | 送餐的**服务员 + 配送员** |

**关键点（这里最容易搞混）**：**"客户端"和"服务器"不是指哪台电脑，而是指"谁扮演什么角色"。**

- 你看网页时，你的电脑是客户端，淘宝服务器是服务器。
- 但你用 BT 下载时，你的电脑**既在下载（客户端），又在给别人上传（服务器）**。
- 同一台电脑，这一刻是客户端，那一刻可能是服务器。角色随时可以互换。

### 0.5 一句话给新手打个底

> 网络世界就三件事：**我（客户端）要什么 → 中间人（网络设备）帮我传 → 对方（服务器）给我什么**。
> 后面的所有章节，都是在把这三件事一层层拆开，看清楚中间到底发生了什么。

## 第 1 章 网络分层的"邮局体系"（OSI 与 TCP/IP）

### 1.1 为什么网络要"分层"？——这是全书最重要的一件事

网络传输是一件**极其复杂**的事：你的微信消息要穿过小区、城市、国家，绕过拥堵，防止丢包，还得让两边的软件能对上话。如果所有功能都堆在一起做，谁都没法写、没法改、没法排查问题。

**分层的思想**：把复杂问题拆成一层层简单的环节，**每一层只负责一件事，各层之间只靠"标准接口"对接**。

#### 生活类比：跨国寄一封快递

你在北京，想寄一封信给美国的朋友。整个过程分了多少个独立环节？

1. 你只负责：**写内容、写收件人地址**（最上层，你只关心"内容"）
2. 快递员负责：**上门取件、打包**（它不管你信里写什么）
3. 分拣中心负责：**根据地址决定走哪条航线**（它只看地址格式，不读信）
4. 运输环节负责：**坐飞机/坐船运过去**（它只管运，不管信的内容和地址对不对）
5. 到了美国，那边再**逐级往下传，最后送到收件人手上**

你完全不需要会开飞机，快递员也不用知道信里写了什么。**每层干好自己那层的事，把剩下的交给上一层或下一层**——这就是分层。

#### 分层带来的三大好处

| 好处 | 说明 |
|------|------|
| **各自独立** | 换一根更好的网线（物理层），不用改浏览器代码（应用层） |
| **分工明确** | 每层只做一件事，出问题好定位："是地址错了（IP），还是路断了（物理）？" |
| **标准化** | 不同厂家做的网卡、路由、软件，只要遵守同一套分层规则，就能互相通信 |

### 1.2 两套分层体系：OSI 七层 与 TCP/IP 四层

| 体系 | 层数 | 用途 | 记住要点 |
|------|------|------|---------|
| **OSI 七层模型** | 7 层 | 国际标准（ISO）制定，主要用于**教学和概念参考** | 概念完整漂亮，但实际互联网没完全照它做 |
| **TCP/IP 四层模型** | 4 层 | **真实互联网运行所遵循的模型** | 我们日常说的、实际用的都是它 |

> **必记**：实际互联网用的是 **TCP/IP 模型**。OSI 七层你只要知道"它存在、更细、教学用"即可，很多书和面试都喜欢拿它们对比。

### 1.3 TCP/IP 四层模型——用"寄快递"贯穿全书

记住这张表，全书所有内容都挂在它上面：

| 层级 | 名字 | 快递类比中的角色 | 主要协议/工具 | 它回答的问题 |
|------|------|----------------|--------------|-------------|
| 第 4 层 | **应用层 Application** | 你写的信**内容** | HTTP、HTTPS、DNS、FTP、SMTP | "信里写什么？" |
| 第 3 层 | **传输层 Transport** | 邮局的**收寄单**（编号、签收凭证） | TCP、UDP | "能不能保证送到？要不要保证？" |
| 第 2 层 | **网络层 Network** | 快递单上的**收件地址** | IP、ICMP、路由器 | "寄到哪个城市哪条街？" |
| 第 1 层 | **链路层 + 物理层** | **货车、公路、红绿灯** | 以太网、Wi-Fi、网卡 | "用哪辆车、走哪条路把货物真的运过去？" |

> **形象记忆口诀**：从上到下是"**内容 → 保证 → 地址 → 搬运**"。
> 就像寄快递：写内容（应用）→ 填寄递单（传输）→ 写地址（网络）→ 交货车（链路/物理）。

### 1.4 每层到底干什么？——逐层一句话 + 详细解释

#### 第 4 层 应用层（离你最近）

- 负责：**产生数据、看懂数据**。你敲的网址、点的按钮、发的文字，都是应用层在生成请求。
- 类比：你写信时的**纸和笔**——只管"写什么内容"。
- 代表协议：HTTP/HTTPS（网页）、DNS（域名翻译）、FTP（传文件）、SMTP/IMAP（邮件）。

#### 第 3 层 传输层

- 负责：**端到端传输**，管"从这台电脑的某个程序，传到那台电脑的某个程序"，并决定要不要保证可靠。
- 类比：邮局的**收寄系统**——决定"这封信要不要挂失补发（可靠）、还是平信发出就不管（不可靠）"。
- 代表协议：TCP（可靠）、UDP（快速）。

#### 第 2 层 网络层

- 负责：**找路/路由**。决定"数据从源机器怎么一跳一跳地走到目标机器"，并给每个设备一个逻辑门牌号（IP）。
- 类比：快递单上的**收件地址 + 干线规划**——"发往哪个城市"。
- 代表协议：IP、ICMP；核心设备：**路由器**。

#### 第 1 层 数据链路层 + 物理层

- 负责：在**同一条物理线路上**，把数据变成**电信号/光信号/无线电波**真正送出去，并解决"同一段线上多个设备怎么排队"。
- 类比：**货车、公路、红绿灯**——真正动手把东西搬过去。
- 代表：以太网（有线）、Wi-Fi（无线）、网卡、网线、光纤。

### 1.5 数据在各层的"变身"：封装与解封装（重中之重）

这是理解网络的**最关键概念**，必须慢慢看。

#### 什么是封装（Encapsulation）？

**封装 = 每经过一层，就给数据套上一个该层的"信封头"（Header）。**

发送时从**上往下**一层层套：

```
你写好的内容（比如"你好"）
    │  应用层产生
    ▼
[传输层] 给内容加一个 TCP 头（写：从哪个端口出、到哪个端口进、包的编号）
    ▼
[网络层] 再在最外层加一个 IP 头（写：源 IP 地址、目的 IP 地址）
    ▼
[链路层] 再加一个以太网头（写：源 MAC 地址、目的 MAC 地址）
    ▼
[物理层] 整包变成电信号/光信号，发出
```

**生活类比（重点）**：
- 你的信（内容）**先在桌上写好**（应用层）
- 塞进一个**文件袋**，袋子上写"寄件人程序、收件人程序、第几件"（TCP 头）
- 再套一个**快递大信封**，信封上写"从哪台电脑、到哪台电脑"（IP 头）
- 最后交给快递员，快递员在面单上再贴一层**分拣标签**（MAC 头）
- 然后货车运走（物理层）

**每一层信封上写的都是"给这一层自己看的地址信息"。**

#### 什么是解封装（Decapsulation）？

接收时从**下往上**一层层拆，和封装完全反过来：

```
收到整包电信号
    ▼
[物理层] 还原成 0/1 数据
    ▼
[链路层] 撕掉以太网头，看目的 MAC 是不是自己，是→把剩下的交上去
    ▼
[网络层] 撕掉 IP 头，看目的 IP 是不是自己，是→交上去
    ▼
[传输层] 撕掉 TCP 头，看端口号，按端口交给对应程序
    ▼
[应用层] 得到干净的内容"你好"，显示给你
```

> **核心结论（背下来）**：**每一层只管自己那一层加的"头"，不拆下面层封装好的内容。封装是逐层套壳，解封装是逐层扒壳。**

### 1.6 常见误区（新手必踩的坑）

| 误区 | 真相 |
|------|------|
| "网络就是一根网线连起来" | 背后是 4 层协议+无数路由器在协同 |
| "协议是软件，可有可无" | 没有协议，两台电脑连上也不知道怎么说话 |
| "分层是多余的" | 不分层，改一层就得重写所有层，工程上不可行 |
| "OSI 七层是实际在用的" | 实际互联网用的是 TCP/IP 四层，OSI 偏教学 |

## 第 2 章 应用层：你直接打交道的那层

### 2.1 应用层是什么？为什么叫"应用"层？

**应用层是最顶上、离人最近的层**。你打开浏览器输入网址、你发微信、你看邮件——**凡是你在"用"的软件产生的网络通信，都是应用层在管**。

- 它负责两件事：**① 生成你要发送的请求；② 看懂对方返回的数据。**
- 类比：它是"**写信的纸笔**"——内容写得好不好、格式对不对，全在这一层决定。

### 2.2 什么是"协议"？（先补这个基础概念）

**协议 = 双方通信时共同遵守的"一套规则/格式"。**

- 两个人说话要有共同语言，不然鸡同鸭讲。
- 两台电脑通信也一样，必须约定：**数据怎么开头、怎么结尾、谁先说话、内容怎么组织**。这套约定就叫**协议（Protocol）**。

> 生活类比：**见面问好是有"协议"的**——"你好！""你好！"双方都按这个格式来，才能顺利开始对话。网络协议就是电脑版的"打招呼规则"。

### 2.3 最关键的协议：HTTP（超文本传输协议）

#### 2.3.1 HTTP 是什么

- 全称：**H**yper**T**ext **T**ransfer **P**rotocol = **超文本传输协议**。
- 作用：**传输网页**。你看到的所有网页，几乎都靠 HTTP 传过来。
- 类比：HTTP 就像"**餐厅点餐的服务规则**"——客人（浏览器）说想吃什么（发请求），厨房（服务器）把菜端上来（返回网页）。

#### 2.3.2 HTTP 的工作模式：请求-响应

HTTP 的工作非常简单，就一个模型：**一问一答**。

```
浏览器  ──(发一个 HTTP 请求 Request)──▶  服务器
浏览器  ◀──(回一个 HTTP 响应 Response)── 服务器
```

- 你每打开一个网页，浏览器可能**发几十上百个请求**（HTML、CSS、JS、图片、视频各一个）。
- 每个请求都要一次"一问一答"，所以网页内容多就会显得慢。

#### 2.3.3 HTTP 的"无状态"特性（重点）

**HTTP 是无状态（Stateless）的**：服务器不记得上一次请求是谁发的、干了什么。

- 类比：去小卖部买完就走，老板不记得你上次买了啥。
- 那电商网站怎么知道"你是谁、你购物车里有啥"？靠 **Cookie**（小饼干）：服务器给你发一个小凭证，你下次来带上它，服务器一看就知道是你。

> **易错点**：别以为"网页是长期连着的一根线"。HTTP 是**每次一问一答、答完就断**的短交易。

#### 2.3.4 常见 HTTP 方法（动词）

| 方法 | 含义 | 类比 | 典型场景 |
|------|------|------|---------|
| **GET** | 获取数据（只读，不发内容） | "我去看看" | 打开网页、搜索 |
| **POST** | 提交数据（把内容发给服务器） | "我填表提交给你" | 登录、发帖、下单 |
| **PUT** | 整体更新资源 | "把我提交的东西整个替换" | 更新用户资料 |
| **PATCH** | 部分更新资源 | "只改我提交的那一部分" | 改昵称不改头像 |
| **DELETE** | 删除资源 | "把这个删掉" | 删除一条记录 |

> **必记区分**：**GET 是"要东西"，POST 是"给东西"。** 千万别搞混。

#### 2.3.5 HTTP 状态码：服务器给你的"回执单"

每次响应，服务器都会带上一个三位数字的状态码，告诉你结果如何：

| 状态码范围 | 含义 | 例子 |
|-----------|------|------|
| 1xx | 服务器正在处理（信息） | 100 Continue |
| **2xx** | **成功** | **200 成功** |
| 3xx | 重定向（东西搬到别处了） | **301/302 请去新地址** |
| 4xx | **客户端出错**（你请求得不对） | **404 你要的东西不存在**、403 无权限、401 未登录 |
| 5xx | **服务器出错**（对方的问题） | **500 服务器内部错误** |

> 生活类比：就像外卖平台的状态——"商家已接单（2xx）"、"订单已转派（3xx）"、"订单信息有误（4xx）"、"商家出餐失败（5xx）"。

### 2.4 HTTPS：给 HTTP 加把"加密锁"

#### 2.4.1 为什么需要 HTTPS？

- **HTTP 是明文传输**：你发的密码、聊天内容，如果被中间人截获，他直接能看懂——就像把写好的信直接寄，路过的人都能读。
- **HTTPS = HTTP + SSL/TLS 加密**：在 HTTP 之外再套一层加密，数据就算被偷走，也看不懂。

#### 2.4.2 HTTPS 具体保护三件事

| 保护项 | 含义 |
|--------|------|
| **加密** | 内容加密，别人偷看也看不懂 |
| **完整性** | 内容没被中途篡改（数据没被换掉） |
| **身份认证** | 你能确认对方真的是"淘宝"，不是骗子网站 |

> 生活类比：
> - HTTP 是**明信片**——任何人捡到都能读。
> - HTTPS 是**带密码锁的密封保险箱**——只有你和收件人有钥匙，中间人打不开也换不了内容。

#### 2.4.3 怎么判断一个网站有没有加密？

- 看网址开头的 **`https://`**（有就是加密）。
- 现在主流网站（百度、淘宝、银行）全部是 HTTPS。地址栏通常有个小锁图标。

### 2.5 DNS：域名系统——把"名字"翻译成"地址"

#### 2.5.1 为什么要 DNS？

- 人类记不住 `220.181.38.148` 这种数字，但记得住 `www.baidu.com`。
- 电脑相反，只认 IP 地址，不认名字。
- **DNS 就是两者之间的"翻译官/电话簿"**。

> 一句话：**DNS = 从"域名"查到"IP 地址"的全球电话簿。**

#### 2.5.2 DNS 查询过程（简化版，但完整）

假设你在浏览器输入 `www.baidu.com`：

```
第 1 步：浏览器问"本地 DNS 服务器"：www.baidu.com 的 IP 是多少？
第 2 步：本地 DNS 如果不知道，就向上问（根服务器→顶级服务器→权威服务器）
第 3 步：一路查到最终 IP 并返回给浏览器
第 4 步：浏览器把结果缓存下来，下次直接查缓存，快很多
```

> 生活类比：**查电话簿**。你只知道同事叫"老王"（域名），翻电话簿（DNS）找到他的号码（IP），才拨得出去（发起访问）。

#### 2.5.3 DNS 的域名结构（简单认识）

`www.baidu.com` 从右往左看：

| 部分 | 含义 |
|------|------|
| `.com` | 顶级域名（商业机构） |
| `baidu` | 二级域名（公司/机构名称） |
| `www` | 三级域名（具体服务，如网页服务） |

> 补充：顶级域名还有 `.cn`（中国）、`.org`（组织）、`.edu`（教育）、`.gov`（政府）等。

### 2.6 端口（Port）：同一个"房子"里找"房间"

#### 2.6.1 为什么需要端口？

一台电脑上可能同时跑着：浏览器（访问网页）、微信（聊天）、邮件客户端（收发邮件）。
数据到了这台电脑，到底**交给哪个程序**？答案就是**端口号**。

> **核心结论**：**IP 找到"哪台电脑"，端口找到"电脑上的哪个程序"。**

#### 2.6.2 端口是什么？

- 端口号是 **0~65535** 之间的数字。
- 一台电脑可以同时开很多端口，每个端口对应一个正在工作的服务/程序。

> 生活类比：一栋楼（电脑）有地址（IP），楼里有好多房间（端口），你要找人（数据）得知道**他住哪个房间（端口号）**。

#### 2.6.3 常用端口速查表（背下来很有用）

| 端口 | 服务 | 全称 |
|------|------|------|
| 80 | HTTP | 超文本传输协议 |
| 443 | HTTPS | 加密网页 |
| 21 | FTP | 文件传输 |
| 22 | SSH | 远程登录 |
| 25 | SMTP | 发送邮件 |
| 110 | POP3 | 收取邮件 |
| 53 | DNS | 域名解析 |

### 2.7 其他常见应用层协议（认识即可）

| 协议 | 全称 | 用途 | 类比 |
|------|------|------|------|
| **FTP** | 文件传输协议 | 上传/下载文件到服务器 | 快递搬家整箱文件 |
| **SMTP** | 简单邮件传输 | 发邮件 | 邮局寄信 |
| **IMAP / POP3** | 邮件接收协议 | 收邮件 | 去邮局取信 |
| **SSH** | 安全外壳 | 远程登录并控制服务器 | 远程操控别人家电脑 |
| **DHCP** | 动态主机配置协议 | 自动给设备分配 IP | 酒店前台自动发房卡 |
| **Telnet** | 远程登录（明文） | 老式远程登录 | 不加密的远程操控 |

> **DHCP 特别说明**：你手机连 Wi-Fi 时"自动获得 IP"，就是 DHCP 干的。**你不用自己设 IP，它帮你自动分配。**

### 2.8 应用层小结（自查）

1. HTTP 是"一问一答"，每次答完就断 —— ✅
2. GET 是"要"，POST 是"给" —— ✅
3. 404 表示"你要的东西不存在" —— ✅
4. HTTPS 比 HTTP 多一层加密 —— ✅
5. DNS 负责"域名 → IP"的翻译 —— ✅
6. IP 找电脑，端口找程序 —— ✅

## 第 3 章 传输层：TCP 与 UDP

### 3.1 传输层管什么？

**传输层管的是"两个程序之间的数据来往"，并且决定"要不要保证可靠"。**

它提供两种风格迥异的协议，你必须彻底分清：

| 维度 | **TCP**（可靠派） | **UDP**（速度派） |
|------|------------------|-----------------|
| 是否保证送达 | 保证（不丢、不乱、不重复） | 不保证 |
| 是否面向连接 | 面向连接（要先"握手"建立关系） | 无连接（拿了就发） |
| 速度 | 相对慢 | 快 |
| 适合场景 | 网页、文件、邮件、聊天 | 视频、语音、游戏、直播 |

> **一句话记忆**：**TCP 讲究"必须送到而且要完整"；UDP 讲究"我马上发，掉了就算了"。**

### 3.2 为什么需要"可靠"？——TCP 解决的痛点

网络世界有个残酷现实：**数据在传输过程中会丢包**。

- 网络拥堵、线缆质量差、路由器排队超时，都可能让某个数据包"消失"。
- 如果发邮件丢了一句话，可能造成重大误会；发银行转账丢了数字，后果更严重。
- 所以需要 TCP 这样的协议，**保证你发的每一个字节都完整、有序、不重复地到达**。

### 3.3 TCP 名字里的"面向连接"是什么意思？

**"连接"= 在正式传数据之前，双方先建立一套"通话关系"**，确认"你在、我在、线路通、双方都准备好了"。

建立这个连接的动作，就是著名的**三次握手**。

### 3.4 三次握手（建立连接）——逐条讲清楚

#### 类比先行：网上约朋友见面

```
第一次：你喊   "喂！你在吗？"             （对应 SYN）
第二次：朋友回 "在！我在！收到你的话了！"  （对应 SYN+ACK）
第三次：你回   "好！那咱们开始聊吧！"     （对应 ACK）
```

三次之后，双方都确认"彼此在线、彼此都能收到对方的信号"，然后才开始传数据。

#### 技术版（面试/考试标准答案）

```
客户端 ── SYN(seq=x) ──────────▶ 服务器    第一次：客户端说"我要建连接，我的初始序号是x"
客户端 ◀─ SYN+ACK(seq=y, ack=x+1) ── 服务器  第二次：服务器说"好，我同意，我的初始序号是y，我确认收到了你的x"
客户端 ── ACK(ack=y+1) ────────▶ 服务器    第三次：客户端说"我确认收到你的y，连接正式建立"
```

#### 为什么必须是三次，不能两次？（高频考点）

- **两次不够**：如果只有两次，客户端可能发了一个连接请求，因为网络拥塞**迟迟没到**，服务器先发出确认。但此时服务器**无法确认客户端是否真的收到了自己的确认**。万一副本来迟到的旧请求又到达服务器，就会造成"一个请求开了两次连接"的混乱。
- **三次才完整**：第三次 ACK 是**客户端给服务器的最终确认**，让服务器确定"客户端确实收到了我的确认"。这样双方都确认无误，连接才能可靠建立。

> **必背**：三次握手的目的 = **让双方都确认"对方在线、双方收发都正常"**。

### 3.5 四次挥手（断开连接）——逐条讲清楚

断开要比建立多一步，共四次。为什么？因为 **TCP 是"全双工"的**——它同时有两条独立通道（你→我 和 我→你），**两边的数据要各自说完再见**。

#### 类比：两个人结束电话

```
第一次：A 说"我说完了，我要挂了"（A 不再发数据）           → FIN
第二次：B 说"好的，我知道了，我这边可能还有话没说完"       → ACK
第三次：B 把剩下的话说完，然后说"我也说完了，可以挂了"     → FIN
第四次：A 说"好，确认收到，挂了吧"                         → ACK
```

#### 技术版

```
客户端 ── FIN ────────────────▶ 服务器   ①客户端说"我不再发数据了"
客户端 ◀─ ACK ───────────────── 服务器   ②服务器确认收到（但服务器还可能继续发数据）
客户端 ◀─ FIN ───────────────── 服务器   ③服务器也说"我也不再发数据了"
客户端 ── ACK ────────────────▶ 服务器   ④客户端最终确认，连接彻底关闭
```

> **重点**：第 2 步和第 3 步之间，服务器可能还在给你发最后一批数据（比如下载文件的收尾）。所以不能合并，必须是 4 步。

### 3.6 TCP 的三大可靠性机制（核心中的核心）

TCP 承诺"不丢、不乱、不重复"，它靠下面三个工具实现：

#### 机制一：序列号 + 确认号（seq / ack）

- **发送方**给每个字节都编一个序号（seq）。
- **接收方**收到后回复确认号（ack）："我收到了到第 N 个字节为止的所有数据。"
- 如果发方发现某个序号迟迟没被确认，就知道它丢了，**重发这一段**。

> 类比：**剧本按页码排列**。你寄出一叠剧本，收到方回复"我只收到第 3 页之前的，第 4 页没收到"，你就把第 4 页重寄。

#### 机制二：超时重传

- 发送方发完数据后，启动一个**定时器**。
- 如果在规定时间内**没收到对方的确认（ACK）**，就认为数据丢了，**自动重发**。

> 类比：**发短信没人回**。等 3 分钟没回信，就再发一遍"收到了吗？"。

#### 机制三：滑动窗口（控制发送速率 + 批量发送）

- 如果每次发一个包等一个确认，效率太低。TCP 允许**一次性连续发送一批数据**（窗口大小内的都发出去）。
- 同时，接收方会告诉发送方"我最多能收多少"（接收窗口），发送方**不能超过这个量猛发**，否则会撑爆接收方。
- 网络拥塞时，窗口还会自动调小，防止把网络堵死。

> 类比：**流水线生产**。工人（发送方）可以连续放一批货（窗口）到传送带上，但数量不能超过仓库（接收方）能放下的量；仓库告诉工人"一次别超过 5 件"，工人就按 5 件一批发。

### 3.7 拥塞控制（TCP 防止把网络堵死）

网络好比高速公路，如果所有车都拼命挤上来，整条路就瘫痪了。TCP 有**拥塞控制**：

| 机制 | 通俗解释 |
|------|---------|
| **慢启动** | 刚开始小心翼翼地慢慢发（先发 1 个、2 个、4 个……翻倍试探） |
| **拥塞避免** | 达到一定速度后改为线性缓慢增长，试探网络极限 |
| **快重传** | 接收方发现某个包缺失，立刻催发"这个包丢了快补发"，不用等超时 |
| **快恢复** | 补发后不从头开始，而是从丢包处附近恢复，减少波动 |

> 新手只需记住一句话：**TCP 会看"路堵不堵"，堵了就自动慢下来，路通了再提速。** 这就是为什么网速会忽快忽慢的原因之一。

### 3.8 UDP：快，但什么都不保证

#### 3.8.1 UDP 是什么

**UDP（User Datagram Protocol，用户数据报协议）**：**无连接、不保证送达**的传输协议。抓到数据直接发，发完就不管了。

#### 3.8.2 为什么有人愿意用它？

因为**放弃可靠性，换来低延迟和高速度**：
- 不用三次握手（省时间）
- 不用确认、不用重传（省带宽、省等待）
- 视频通话里丢一帧画面，观众根本察觉不到；但如果要求"重传这帧"，反而造成卡顿，体验更差。

#### 3.8.3 UDP 的典型应用场景

| 场景 | 为什么用 UDP |
|------|------------|
| **视频直播 / 语音通话** | 丢几帧不影响观看，重传反而卡 |
| **在线游戏** | 要极低延迟，重传没意义（操作已过时） |
| **DNS 查询** | 数据量极小，一次 UDP 就够 |
| **视频会议** | 实时性优先，丢包可容忍 |

#### 3.8.4 一个对比帮你看清差异

| 场景 | TCP 的表现 | UDP 的表现 |
|------|-----------|-----------|
| 视频通话卡顿 | 为补一帧卡住，越来越卡 | 丢那几帧，继续流畅播放 |
| 银行转账 | 必须保证分毫不差 | 不敢用（会丢钱） |

> **类比总结**：
> - TCP = **寄挂号信**：慢，但每件都要签收凭证，保证送到。
> - UDP = **对讲机喊话**：实时，但对方没听见就没了，你也无所谓。

## 第 4 章 网络层：IP 地址与路由器

### 4.1 网络层管什么？

**网络层负责"在两个网络之间找到路"，解决"数据包该往哪里走"的问题。**

打个比方：链路层是"把货装上车"（管同一段路上怎么运），网络层是"看地图规划路线"（管跨城市怎么走）。核心成员就是 **IP 协议** 和 **路由器**。

### 4.2 IP 地址：每台设备的"门牌号"

#### 4.2.1 什么是 IP 地址

- **IP 地址** = 每台联网设备在网络世界里的**唯一"门牌号"**。
- 数据要发给谁，必须先知道谁的 IP。就像寄快递必须先写收件地址。

> 类比：小区每一栋、每一户都有**门牌号**（IP）。没有门牌号，快递员（数据）就找不到你家。

#### 4.2.2 IPv4：我们现在主要用的版本

- IPv4 由 **4 组 0~255 的数字**组成，用点隔开。例：`192.168.1.100`。
- 一个 IP 最多只有约 **42 亿**个，而全球设备早已远超这个数，所以**不够用了**。

#### 4.2.3 IPv6：新一代，解决不够用

- IPv6 更长（8 组十六进制），如 `2001:0db8:0000:0000:0000:ff00:0042:8329`。
- 地址数量多到**宇宙的沙子数都算不完**，彻底解决不够用问题。
- 现在很多新设备、新网站已经在用 IPv6，但 IPv4 仍广泛存在。

### 4.3 IP 地址的两部分：网络号 + 主机号

一个 IP 地址内部其实分两段：

| 部分 | 含义 | 类比 |
|------|------|------|
| **网络号（network）** | 你属于**哪个网段**（哪栋楼/哪个小区） | 省份 + 城市 |
| **主机号（host）** | 你在**这个网段里的第几台**（具体哪户） | 街道 + 门牌 |

#### 子网掩码：用来"划界线"的尺子

- **子网掩码（Subnet Mask）** 告诉电脑：IP 里**哪几位是网络号、哪几位是主机号**。
- 例：IP `192.168.1.100`，子网掩码 `255.255.255.0`，说明前 3 组（192.168.1）是网络号，最后 1 组（100）是主机号。

> 类比：**门牌号编码规则**。约定"前三位代表小区、后一位代表户号"，那么"192.168.1"就是小区，"100"就是这小区里的第 100 户。

### 4.4 公网 IP 与私网 IP（必须分清）

| 类型 | 说明 | 例子 | 类比 |
|------|------|------|------|
| **公网 IP** | **全球唯一**，互联网上其他设备可以直接访问 | 你看到的网站服务器 IP | 一个全国通用的**公开门牌** |
| **私网 IP** | **局域网内部**使用的地址，外网无法直接访问 | `192.168.x.x`、`10.x.x.x`、`172.16.x.x` | 小区内部的**内部房号** |

> **重点**：你家里的路由器给手机、电脑分配的都是私网 IP（192.168 开头），因为全球公网 IP 不够用，不能每家每户都发一个公网 IP。

### 4.5 NAT：让"私网"也能上公网的关键技术

- **NAT（Network Address Translation，网络地址转换）**：把家里所有的私网 IP，统一映射成路由器那**一个公网 IP** 出去上网。
- 回复的数据回来时，NAT 再根据"记录"把数据分回对应那台设备。

> 类比：**酒店前台**。每个房间有自己的内部房号（私网），对外统一用酒店总机号码（公网）。外面打电话进来，前台先接，再转接到对应房间。

### 4.6 路由器（Router）：网络的"快递分拣中心"

#### 4.6.1 路由器干什么

- 路由器根据 **IP 地址**，决定数据包"**下一步往哪个网络转发**"。
- 它连接不同的网络（比如你家局域网和互联网），是跨网络的"分拣中心"。

#### 4.6.2 路由表：路由器的"地图"

- 每个路由器内部有一张**路由表（Routing Table）**，上面写着：
  - "要去哪些网段，应该往哪个出口走"
  - "如果找不到明确路线，走默认出口（默认网关）"
- 数据包每经过一个路由器，路由器查一次表，指向下一站，直到到达目标网段。这个过程叫**路由（Routing）**。

> 类比：**高速公路的出口引导牌**。每到一个出口，都有一块牌子告诉你"去 xx 城市走哪条道"。数据包就像一辆车，一路看牌子、一路往下走，最后到达目的地。

#### 4.6.3 简单模拟一次"跳数"

```
你的电脑(192.168.1.100) → 家里路由器 → 电信骨干路由器 → ... → 目标网站服务器
       每一跳（hop）都由一个路由器查表转发
```

> 你运行 `tracert`（Windows）或 `traceroute`（Linux）命令，能看到这个包经过了哪些路由器，非常直观。

### 4.7 ICMP：网络层的"体检工具"

- **ICMP（Internet Control Message Protocol）** 用来**检测网络通不通**。
- 最常用的命令：**`ping`**。你 ping 一个地址，就是发 ICMP 消息问"你在吗？多久能回？"。
- 网站打不开时，第一步就 ping 一下，看是网络断了，还是网站本身挂了。

### 4.8 网络层小结（自查）

1. IP = 设备的门牌号，IPv4 4 组数字，IPv6 更长 —— ✅
2. 子网掩码用来划分"网络号/主机号" —— ✅
3. 公网 IP 全球唯一，私网 IP 只在局域网内用 —— ✅
4. NAT 把私网 IP 映射成公网 IP 才能上网 —— ✅
5. 路由器查路由表，把数据包一跳一跳转发到目标 —— ✅
6. ping 用 ICMP 检测网络通不通 —— ✅

## 第 5 章 数据链路层与物理层：把数据变成电信号

### 5.1 这一层管什么？

到了这一层，前面所有"信封"（数据包）都要**真正上车出发**了。这一层负责：
1. **在同一段物理线路上**把数据帧传给紧挨着的下一台设备。
2. 把 0/1 数据变成**电信号、光信号、无线电波**实际发出去。

### 5.2 MAC 地址：网卡自带的"指纹"

#### 5.2.1 什么是 MAC 地址

- **MAC 地址（Media Access Control Address）** = 每块网卡**出厂时就烧录**的**全球唯一物理地址**。
- 形如：`AA:BB:CC:DD:EE:FF`（48 位，6 组十六进制）。

#### 5.2.2 IP 和 MAC 的分工（高频考点）

| | IP 地址 | MAC 地址 |
|--|--------|---------|
| 性质 | 逻辑地址，**可以改** | 物理地址，**烧死不可改** |
| 作用 | 标明"最终目的地" | 标明"紧挨着的下一站" |
| 范围 | 跨网络有效（全球） | 只在同一局域网内有效 |
| 类比 | 目的地城市的**地址** | 眼前这辆车/这条街的**牌号** |

> **核心结论**：数据包从源到目标，**IP 地址全程不变**（一直是最终目的地），但**每经过一段链路，MAC 地址就换一次**（换成本段这一站的牌号）。
>
> 类比：你去外地旅游，**目的地地址（IP）从头到尾不变**；但你**每坐一段车，车次号（MAC）都不一样**。

### 5.3 ARP：怎么根据 IP 找到 MAC？

- 问题：知道了对方 IP，但同一局域网内真正传数据要靠 MAC。怎么从 IP 找到 MAC？
- 答案：**ARP（Address Resolution Protocol，地址解析协议）**。
- ARP 在局域网里广播问："谁的 IP 是 192.168.1.5？请把 MAC 告诉我。" 对应设备回答后，双方就开始用 MAC 通信。

> 类比：你在小区广播问"192.168.1.5 的住户在吗？报一下你的身份证号（MAC）"。那人回答了，你就记下，下次直接找。

### 5.4 交换机（Switch）：局域网内部的"智能分发员"

#### 5.4.1 交换机干什么

- 交换机工作在第 2 层（数据链路层），**根据 MAC 地址**，在**同一个局域网内部**把数据帧准确转发给目标设备。
- 它比路由器"简单"：不看 IP，只在同一个网段内部转发。

#### 5.4.2 交换机怎么知道该转发给谁？

- 交换机内部维护一张 **MAC 地址表**（端口 ↔ MAC 的对应关系）。
- 第一次收到某个 MAC 的包时不知道出口，就广播（问所有人）；以后就知道了，直接精准转发。

> 类比：**小区物业**。它记着"哪户住在哪栋哪层"，送信（数据帧）时直接送到户，不用挨家敲门。

### 5.5 路由器 vs 交换机（必考对比）

| 对比项 | **交换机** | **路由器** |
|--------|-----------|-----------|
| 依据地址 | **MAC 地址** | **IP 地址** |
| 作用范围 | **局域网内部** | **连接不同网络 / 上网** |
| 类比 | 小区内部的门牌引导员 | 跨城市的快递总中心 |
| 会不会看 IP | 不看，只看 MAC | 专门看 IP |

> **简单记忆**：**交换机在"屋里"分信，路由器在"屋与屋之间"带路。** 你家光猫后面一般先接路由器，路由器再接交换机（如果需要更多网口）。

### 5.6 物理层：真正"动手"的层

物理层是最底层，管**信号的物理传输**：

| 介质 | 特点 | 场景 |
|------|------|------|
| **双绞线（网线）** | 便宜、短距离（<100m） | 家里、办公室有线 |
| **光纤** | 快、远、抗干扰 | 宽带入户、跨城骨干 |
| **无线电波（Wi-Fi/4G/5G）** | 无线、灵活 | 手机、笔记本 |

> 物理层做的事：把 0 和 1 变成"有电压/没电压"、"有光/没光"、"有信号/没信号"，然后沿介质传出去，接收端再还原成 0/1。

### 5.7 以太网：有线局域网的标准

- **以太网（Ethernet）** 是目前**最主流的局域网技术**（你电脑插网线用的就是它）。
- 它规定了：数据帧的格式、MAC 地址怎么用、设备怎么避免"同时说话"（冲突避免）等。

### 5.8 链路层小结（自查）

1. MAC 是网卡出厂自带的物理地址，不可改 —— ✅
2. IP 全程不变，MAC 每段一换 —— ✅
3. ARP 负责"IP → MAC"的解析 —— ✅
4. 交换机看 MAC 在局域网内部转发；路由器看 IP 跨网络转发 —— ✅
5. 物理层负责把 0/1 变成电/光/无线电信号 —— ✅

## 第 6 章 一次完整的"打开网页"之旅

把前面所有章节串起来，完整走一遍"从输入网址到看到网页"的全过程。这是检验你是否真正理解网络分层的终极测试。

### 场景

你在电脑浏览器地址栏输入：`https://www.example.com`

### 逐步走一遍（每一步都说明是哪一层在干活）

| 步骤 | 动作 | 属于哪一层 | 通俗解释 |
|------|------|-----------|---------|
| 1 | 你输入网址，浏览器发起访问 | 应用层 | 你写了"信的内容"：我要访问 example.com |
| 2 | **DNS 查询**：把 `www.example.com` 解析成 IP（如 93.184.216.34） | 应用层（DNS） | 查电话簿，拿到对方的门牌号 |
| 3 | **三次握手**：与服务器建立 TCP 连接 | 传输层（TCP） | 先互相确认"你在、我在、线路通" |
| 4 | 浏览器发送 **HTTP GET 请求**（要首页） | 应用层（HTTP） | 你说"你好，我要首页那封文件" |
| 5 | 请求数据被**封装**：加 TCP 头 → 加 IP 头 → 加 MAC 头 | 传输层→网络层→链路层 | 内容装进信封，写程序号、写地址、贴分拣标签 |
| 6 | **路由转发**：数据包经路由器一跳一跳送到服务器所在网络 | 网络层 | 快递过一个个分拣中心，朝目的地推进 |
| 7 | 沿途每一段，物理层把包变成**电/光信号**发出 | 物理层 | 货车在公路上跑 |
| 8 | 服务器收到包，逐层**解封装**：剥 MAC → 剥 IP → 剥 TCP → 得到 HTTP 请求 | 链路层→网络层→传输层→应用层 | 快递一层层拆开，最后看到信内容 |
| 9 | 服务器处理请求，把网页内容（HTML 等）**再封装**返回 | 应用层 + 各层 | 服务器写好回信，同样套信封寄回 |
| 10 | 你的电脑用 **TCP 确认/重传**保证每个包完整到达 | 传输层 | 收到的是完整、顺序正确的整套网页 |
| 11 | 浏览器**解封装**得到 HTML/CSS/JS，**渲染成网页画面**显示给你 | 应用层 | 拆信读完，排版显示成你看到的页面 |

### 一张图（从上到下，数据旅行一个来回）

```
你的浏览器（应用层）
      │ ①输入网址 → ②DNS 查 IP → ③TCP 三次握手 → ④发 HTTP GET
      ▼
传输层  TCP 头 + 内容（端口、包号、可靠性）
      ▼
网络层  IP 头（源IP → 目的IP）   ← 路由器沿路转发
      ▼
链路层  MAC 头（源MAC → 下一站MAC）← 交换机在局域网内转
      ▼
物理层  变成电/光信号，走网线/光纤/无线
━━━━━━━━━━━━ 互联网大海（无数路由器跳来跳去） ━━━━━━━━
      ▼
服务器物理层 收到信号 → 解封装：剥 MAC → 剥 IP → 剥 TCP → 看到 HTTP 请求
      ▼
服务器应用层 处理请求，返回 HTML
      ▼
（按同样方式一层层封装，原路返回）
      ▼
你的浏览器 解封装 → 渲染网页 ✅ 你看到了页面！
```

### 全程观察：分层的好处一目了然

- 浏览器只关心"HTTP 内容对不对"（应用层）。
- TCP 只关心"包完整到达没"（传输层）。
- 路由器只关心"IP 地址往哪转"（网络层）。
- 网卡只关心"MAC 到没到、信号发出去没"（链路/物理层）。
- **每一层都不知道其他层的细节，但协作起来，完整完成了一次网页浏览。**

> **这就是计算机网络的精髓：复杂系统靠分层协作，各司其职、互不干扰。**

## 第 7 章 常见名词速查表 与结尾

### 7.1 高频名词一表打尽

| 名词 | 一句话解释 |
|------|-----------|
| **客户端 Client** | 主动发请求的一方（浏览器、App） |
| **服务器 Server** | 响应请求、提供服务的一方 |
| **协议 Protocol** | 双方通信时共同遵守的规则 |
| **TCP** | 可靠、面向连接的传输协议（保证完整送达） |
| **UDP** | 快速、无连接的传输协议（不保证送达） |
| **三次握手** | 建立 TCP 连接的三步确认过程（SYN→SYN+ACK→ACK） |
| **四次挥手** | 断开 TCP 连接的四步告别（各自说再见） |
| **IP 地址** | 设备的网络门牌号（逻辑地址，可改） |
| **MAC 地址** | 网卡出厂自带的物理地址（不可改） |
| **端口 Port** | 电脑上区分不同程序的号码 |
| **DNS** | 把"域名"翻译成"IP 地址"的全球电话簿 |
| **HTTP** | 网页传输协议（明文） |
| **HTTPS** | 加了加密锁（SSL/TLS）的 HTTP |
| **路由 Routing** | 路由器依据 IP 把数据包一跳一跳转发的过程 |
| **路由表** | 路由器内部"去哪网段往哪走"的地图 |
| **NAT** | 把私网 IP 映射成公网 IP 的技术 |
| **子网掩码** | 划分"网络号/主机号"的尺子 |
| **公网 IP / 私网 IP** | 全球唯一可访问 / 局域网内部使用 |
| **交换机** | 看 MAC，局域网内部转发 |
| **路由器** | 看 IP，跨网络转发 |
| **封装 / 解封装** | 每层加头 / 每层剥头 |
| **ARP** | 根据 IP 找到同一局域网内 MAC 的协议 |
| **ping** | 用 ICMP 检测网络通不通的命令 |

### 7.2 全书知识自查（能答出来=毕业）

1. **计算机网络是什么？** 把多台设备连起来，交换信息、共享资源的系统。
2. **为什么要分层？** 把复杂问题拆成各司其职的简单环节，好写、好改、好查。
3. **TCP/IP 四层是？** 应用层 → 传输层 → 网络层 → 链路层/物理层。
4. **封装/解封装是什么？** 发送逐层加头，接收逐层剥头，每层只认自己的头。
5. **HTTP 和 HTTPS 区别？** HTTPS 多了一层 SSL/TLS 加密。
6. **GET 和 POST 区别？** GET 是"要"，POST 是"给"。
7. **404 是什么意思？** 你要的资源不存在（客户端错误）。
8. **DNS 干什么？** 域名 → IP 的翻译。
9. **IP 和端口的分工？** IP 找电脑，端口找程序。
10. **TCP 和 UDP 区别？** TCP 可靠慢、UDP 快不可靠。
11. **三次握手为什么三次？** 让双方都确认"在线、收发正常"。
12. **IP 和 MAC 区别？** IP 逻辑可改全程不变，MAC 物理不可改每段一换。
13. **路由器 vs 交换机？** 路由器看 IP 跨网络，交换机看 MAC 局域网内。
14. **NAT 干什么？** 私网 IP 映射成公网 IP 上网。
15. **打开网页的完整流程？** 输入网址→DNS→三次握手→HTTP 请求→封装→路由→解封装→返回→渲染。

### 7.3 送给小白的两条建议

1. **用命令亲手验证一下**（零风险、很有成就感）：
   - `ping www.baidu.com` → 看网络通不通（ICMP）。
   - `tracert www.baidu.com` → 看数据包经过哪些路由器（路由）。
   - `ipconfig`（Windows）→ 看自己的 IP、子网掩码、默认网关。
   - `nslookup www.baidu.com` → 手动查 DNS。
2. **遇到网络问题先分层定位**：网页打不开时，从上往下排查：
   - 应用层：是网站 404/500 了吗？（换个网站试试）
   - 传输层：是不是连接被防火墙拦了？
   - 网络层：ping 能通吗？（通→网络没问题；不通→可能 DNS/网关问题）
   - 链路/物理层：网线松了？Wi-Fi 断了吗？
